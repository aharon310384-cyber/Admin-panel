# Автодеплой через GitHub Actions

Обновление рабочего сервера (Timeweb, `/opt/postmanfox`, PM2-процесс `postmanfox`) по кнопке в GitHub: Actions → **«Сервер»** → Run workflow.

| Команда | Что делает |
|---|---|
| `status` | Только смотрит: какая версия стоит и сколько коммитов в GitHub новее, изменённые файлы, база, PM2, автозапуск после перезагрузки, ответ админки, диск, память, нужна ли перезагрузка |
| `deploy` | Выкатывает `refactor/model-v2`: бэкап базы (`backup-db.sh`) → остановка админки → новый код → `npm ci`, если менялись зависимости → `prisma db push` → `npm run db:upgrade` → сборка → запуск → проверка, что админка отвечает 200 |

Если на шаге после остановки что-то упало, `deploy` возвращает код к прежней версии, собирает и запускает её. База при этом не откатывается: свежий бэкап лежит в `backups/`. Если на сервере кто-то вручную изменил файлы программы, `deploy` отказывается и ничего не трогает.

Админка недоступна около минуты, пока идёт сборка.

## Как устроено

- `.github/workflows/server.yml` — задача GitHub Actions. Подключается к серверу по SSH и передаёт команду.
- `/usr/local/bin/postmanfox-ci` — точка входа на сервере. Ключ GitHub может выполнить **только её**: ограничение `command=…,restrict` в `authorized_keys`. Она получает свежий `scripts/deploy/server.sh` из `origin/refactor/model-v2` и запускает его.
- `scripts/deploy/server.sh` — сами команды `status` и `deploy`. Меняется обычным pull request, на сервер руками ходить не нужно.
- `npm run db:upgrade` — все обновления данных по порядку. Каждое можно запускать повторно. Новое обновление данных добавляется в эту команду.

Журналы задач видны всем, пока репозиторий публичный. Поэтому скрипт не выводит секреты, адреса и данные клиентов.

## Настройка (один раз)

### 1. Ключ на компьютере (PowerShell)
```powershell
ssh-keygen -t ed25519 -C github-ci-postmanfox -f $HOME\.ssh\github-ci
```
На вопросы про passphrase — дважды **Enter** (без пароля: ключом пользуется GitHub без человека).

### 2. Точка входа на сервере (консоль Timeweb, под root)
Сначала напечатать руками, чтобы вставка работала: `bind 'set enable-bracketed-paste off'`. Затем вставить:
```bash
cat > /usr/local/bin/postmanfox-ci <<'EOF'
#!/bin/bash
set -euo pipefail
cd /opt/postmanfox
git fetch -q origin refactor/model-v2
git show origin/refactor/model-v2:scripts/deploy/server.sh > /root/.postmanfox-server.sh
exec bash /root/.postmanfox-server.sh "${SSH_ORIGINAL_COMMAND:-status}"
EOF
chmod 755 /usr/local/bin/postmanfox-ci && echo "Точка входа установлена"
```
Так точка входа установлена на рабочем сервере (2026-10-16). Если консоль Timeweb сбоит на многострочной вставке, шаги 2 и 3 можно сделать одной строкой: прислать Claude **публичный** ключ (`github-ci.pub`, он не секретный), и он соберёт команду с ключом внутри.

### 3. Публичный ключ на сервер
На компьютере (PowerShell) скопировать публичный ключ:
```powershell
Get-Content $HOME\.ssh\github-ci.pub | Set-Clipboard
```
На сервере вставить команду, а на вопрос `Публичный ключ:` — вставить скопированное:
```bash
read -p "Публичный ключ: " KEY; KEY=${KEY%$'\r'}; case "$KEY" in "ssh-ed25519 "*" github-ci-postmanfox") install -d -m 700 /root/.ssh && touch /root/.ssh/authorized_keys && sed -i '/github-ci-postmanfox/d' /root/.ssh/authorized_keys && echo "command=\"/usr/local/bin/postmanfox-ci\",restrict $KEY" >> /root/.ssh/authorized_keys && chmod 600 /root/.ssh/authorized_keys && echo "Ключ добавлен";; *) echo "Это не публичный ключ github-ci-postmanfox";; esac
```
Проверка точки входа на сервере:
```bash
/usr/local/bin/postmanfox-ci status
```

### 4. Секреты в GitHub
Settings → Secrets and variables → Actions → New repository secret:

| Имя | Значение | Как получить (PowerShell) |
|---|---|---|
| `DEPLOY_HOST` | `64.188.58.224` | — |
| `DEPLOY_USER` | `root` | — |
| `DEPLOY_SSH_KEY` | приватный ключ целиком | `Get-Content $HOME\.ssh\github-ci -Raw \| Set-Clipboard` |

После того как секрет `DEPLOY_SSH_KEY` сохранён, приватный ключ на компьютере больше не нужен: `Remove-Item $HOME\.ssh\github-ci`.

Ключ сервера в секретах не хранится. Задача сама получает его с сервера и сверяет с отпечатком `HOST_FINGERPRINT` в `server.yml`. Если не совпал, задача останавливается и не подключается. Отпечаток меняется только при переустановке сервера: узнать новый — `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` в консоли сервера, затем поправить `server.yml`.

### 5. Основная ветка
Settings → General → Default branch → `refactor/model-v2`. GitHub показывает кнопку запуска задачи только для задач из основной ветки.

## Если репозиторий станет закрытым
Сервер забирает код из GitHub без пароля, пока репозиторий публичный. Перед тем как сделать его закрытым, на сервер нужно добавить deploy key (ключ только для чтения) и переключить `origin` на адрес `git@github.com:…`.
