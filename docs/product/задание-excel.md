# Задание: Excel → база

Для рабочего чата «админка». Решения владельца 2026-10-18/19, подробно — `docs/product/будущее.md`, раздел 11.
Начинать **после шагов 2 и 3** переделки «из кода в настройки» (тарифы только из базы, курс только из настроек): загрузка опирается на них. Шаг 4 (цвета) ждать не нужно.

## Как работает владелец
Рабочий файл в **WPS Office** (Windows, английская версия). Лист `ALL 6`, **одна строка — одна посылка**. Колонки и их смысл — `docs/research/system-architecture.md`, разделы 1.4 и 5. Макросы VBA в WPS владельца недоступны (кнопки серые).

## Кнопка в строке (план А)
- В строке — ссылка «Отправить» (формула `ГИПЕРССЫЛКА` / `HYPERLINK`), работает в WPS без макросов.
- Нажатие открывает страницу админки с данными строки → владелец проверяет → «Сохранить» → ответ «Сохранено, PS-…» или «Ошибка: …».
- Вход в админку уже выполнен — ключ в файле не хранится.
- Повторное нажатие обновляет, не задваивает (ключ — номер задачи).
- Позже, как улучшение: отправка «без окна» через Python Script Editor или JS-макросы WPS.
- План Б (если А не выйдет): страница «Загрузка из Excel» — файл → что нашлось → «Загрузить».

## Строка → документы
1. **Заказ** — из «большой ячейки»: входящий трек-номер, товар с ценой, получатель, адрес, телефон. Несколько входящих треков — несколько заказов.
2. **Задача** — на основании заказа, номер из `order_number` (например `SM2992UAE`).
3. **Посылка** — создаётся задачей.
Время: заказ — T, задача — T + 10 с, посылка — T + 20 с. T — полная дата отправки из строки, если есть; иначе — момент нажатия.

## Правила
1. Клиент — по первым **двум буквам** номера (`SM…` → клиент `SM`). Нет клиента — попросить создать. `ABC` — служебный клиент владельца для проверок.
2. Получатель — из **списка получателей этого клиента** (жёстко привязан к клиенту). Нет — владелец заполняет сам, затем всё связывается с заказом, задачей, посылкой.
3. Страна — из адреса получателя, ставится в конце номера задачи. **Тариф — по стране из базы.** Колонка `LR` в файле — упрощение владельца, система её не повторяет.
4. Цена файла сверяется с ценой системы; расхождение — предупреждение, берётся цена системы, решает владелец.
5. Курс — из колонки «Курс» (правило курса: считает сама — из настроек; из Excel — из файла; старые посылки не пересчитываются).
6. Услуги — сначала в заказ, потом в задачу и посылку. Основные: консолидация, проверка, фотоотчёт, оставить оригинальную упаковку.
7. «+» в колонке «Оплата» — посылка оплачена.
8. Большую ячейку разбирает `lib/ai-order-parser.ts`; **сначала проверить, что он разбирает правильно**; результат показывается до сохранения.
9. При загрузке старых строк **сообщения клиентам не отправлять**.
10. Промежуточные складские документы (сортировка, приём, сборка, упаковка, взвешивание) для истории не создавать; вес — сразу в посылку.
11. 17TRACK — только посылки последних 60 дней.
12. Международный трек — из колонки «Номер посылки».

## Порядок
Каждый шаг — отдельный PR. Сначала проверка разборщика на нескольких настоящих строках (клиент `ABC`), потом одна строка целиком, потом остальное. Вопросы — владельцу.

## Ход работы
- **Шаг 1 — проверка разборщика (2026-10-19).** «Склад» → «Загрузка из Excel» (`/import/excel`): вставить большую ячейку строки, номер строки и курс → «Разобрать». Показывает заказы (входящий трек, товар, кол-во, цена ¥ и $, пожелания) и получателя (ФИО, адрес, город, индекс, страна, телефон); клиента — по буквам в начале номера (`SM2992UA` → `SM`, `ABC0001UA` → `ABC`); есть ли получатель в списке получателей клиента. **Ничего не сохраняется.**
  - Проверка ответа ИИ по тексту ячейки: ✓ — значение есть в тексте, ⚠ — нет (ИИ мог ошибиться или додумать); предупреждение, если в тексте есть похожий на трек номер, которого нет в разборе; страны нет в справочнике; клиента или получателя нет.
  - «Скопировать для чата» — итог проверки текстом, чтобы прислать в чат.
  - Разборщик: `parseExcelInfo` в `lib/ai-order-parser.ts` (заказы + получатель), проверка по тексту — `lib/excel-check.ts`, действие — `actions/excel-import.ts`, страница — `components/import/excel-check.tsx`.
  - Юани в доллары переводит программа по курсу, а не ИИ: в массовом вводе заказов — курс из «Финансы → Курс» (раньше было вписано 7,1), в загрузке из Excel — курс строки.
  - Дальше: владелец проверяет несколько настоящих строк клиента `ABC` и присылает итог; правим разборщик по ошибкам → шаг 2 — одна строка целиком (заказ → задача → посылка).
