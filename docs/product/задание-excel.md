# Задание: Excel → база

Для рабочего чата «админка». Решения владельца 2026-10-18/19, подробно — `docs/product/будущее.md`, раздел 11.
Начинать **после шагов 2 и 3** переделки «из кода в настройки» (тарифы только из базы, курс только из настроек): загрузка опирается на них. Шаг 4 (цвета) ждать не нужно.

## Как работает владелец
Рабочий файл в **WPS Office** (Windows, английская версия). Лист `ALL 6`, **одна строка — одна посылка**. Колонки и их смысл — `docs/research/system-architecture.md`, разделы 1.4 и 5. Макросы VBA в WPS владельца недоступны (кнопки серые).

## Кнопка в строке (план А)
- В строке — ссылка «Отправить» (формула `ГИПЕРССЫЛКА` / `HYPERLINK`), работает в WPS без макросов.
- Нажатие открывает страницу админки с данными строки → владелец проверяет → «Сохранить» → ответ «Сохранено, PS-…» или «Ошибка: …».
- Вход в админку уже выполнен — ключ в файле не хранится.
- Повторное нажатие обновляет, не задваивает (ключ — номер задачи).
- Позже, как улучшение: отправка «без окна» через Python Script Editor или JS-макросы WPS.
- План Б (если А не выйдет): страница «Загрузка из Excel» — файл → что нашлось → «Загрузить».

## Строка → документы
1. **Заказ** — из «большой ячейки»: входящий трек-номер, товар с ценой, получатель, адрес, телефон. Несколько входящих треков — несколько заказов.
2. **Задача** — на основании заказа, номер из `order_number` (например `SM2992UAE`).
3. **Посылка** — создаётся задачей.
Время: заказ — T, задача — T + 10 с, посылка — T + 20 с. T — полная дата отправки из строки, если есть; иначе — момент нажатия.

## Правила
1. Клиент — по первым **двум буквам** номера (`SM…` → клиент `SM`). Нет клиента — попросить создать. `ABC` — служебный клиент владельца для проверок.
2. Получатель — из **списка получателей этого клиента** (жёстко привязан к клиенту). Нет — владелец заполняет сам, затем всё связывается с заказом, задачей, посылкой.
3. Страна — из адреса получателя, ставится в конце номера задачи. **Тариф — по стране из базы.** Колонка `LR` в файле — упрощение владельца, система её не повторяет.
4. Цена файла сверяется с ценой системы; расхождение — предупреждение, берётся цена системы, решает владелец.
5. Курс — из колонки «Курс» (правило курса: считает сама — из настроек; из Excel — из файла; старые посылки не пересчитываются).
6. Услуги — сначала в заказ, потом в задачу и посылку. Основные: консолидация, проверка, фотоотчёт, оставить оригинальную упаковку.
7. «+» в колонке «Оплата» — посылка оплачена.
8. Большую ячейку разбирает `lib/ai-order-parser.ts`; **сначала проверить, что он разбирает правильно**; результат показывается до сохранения.
9. При загрузке старых строк **сообщения клиентам не отправлять**.
10. Промежуточные складские документы (сортировка, приём, сборка, упаковка, взвешивание) для истории не создавать; вес — сразу в посылку.
11. 17TRACK — только посылки последних 60 дней.
12. Международный трек — из колонки «Номер посылки».

## Порядок
Каждый шаг — отдельный PR. Сначала проверка разборщика на нескольких настоящих строках (клиент `ABC`), потом одна строка целиком, потом остальное. Вопросы — владельцу.

## Ход работы

Показывает заказы (входящий трек, товар, кол-во, цена ¥ и $, пожелания) и получателя (ФИО, адрес, город, индекс, страна, телефон); клиента — по буквам в начале номера (`SM2992UA` → `SM`, `ABC0001UA` → `ABC`); есть ли получатель в списке получателей клиента. **Ничего не сохраняется.**
  - Проверка ответа ИИ по тексту ячейки: ✓ — значение есть в тексте, ⚠ — нет (ИИ мог ошибиться или додумать); предупреждение, если в тексте есть похожий на трек номер, которого нет в разборе; страны нет в справочнике; клиента или получателя нет.
  - «Скопировать для чата» — итог проверки текстом, чтобы прислать в чат.
  - Разборщик: `parseExcelInfo` в `lib/ai-order-parser.ts` (заказы + получатель), проверка по тексту — `lib/excel-check.ts`, действие — `actions/excel-import.ts`, страница — `components/import/excel-check.tsx`.
  - Юани в доллары переводит программа по курсу, а не ИИ: в массовом вводе заказов — курс из «Финансы → Курс» (раньше было вписано 7,1), в загрузке из Excel — курс строки.
  - Дальше: владелец проверяет несколько настоящих строк клиента `ABC` и присылает итог; правим разборщик по ошибкам → шаг 2 — одна строка целиком (заказ → задача → посылка).
- **Правки владельца по шагу 1 (2026-10-19):** поле «Курс» убрано — юани в доллары по курсу из «Финансы → Курс»; поле «Задача (номер строки)»; колонки «Комментарий клиента» (идёт в заказ, клиент видит его в кабинете) и «Услуги»; трек посылки до получателя (DHL 00340…, почтовые CB…DE / EV…CN / LC…MG, Meest MGRMY…) показывается отдельно и не считается пропущенным входящим треком; получатель у клиента ищется и по ФИО в любом порядке слов.

- **Строка OG4283AE (2026-10-19): один трек — одна строка, наименование как в ячейке.**
  - Товары с одним входящим треком показываются одной строкой (№ — номер трека), под ней его товары; в «Скопировать для чата» — `1. трек SF1577439745972 · Сумка · 1 шт · ¥6900.00 / $971.83, Платок · 1 шт · ¥450.00 / $63.38`. В базе это по-прежнему несколько заказов с одним треком (правило «Заказ = товар», `docs/product/документооборот.md`); документы склада по коробке — по треку.

- **Шаг 2 — строка целиком → заказы → задача → посылка (2026-10-19).** «Склад» → «Загрузка из Excel». Страница проверки большой ячейки (шаг 1) заменена.
  - **Колонки листа** — настройка вверху страницы: буква Excel для каждого поля (`ExcelImportSettings`, не в коде). Строку копируют начиная с колонки номера строки.
  - Вставить строку → «Разобрать» → видно, что будет сохранено → «Сохранить в базу». Повторно та же строка → «Обновить в базе» (ключ — номер задачи): заказы обновляются по порядку, лишние помечаются удалёнными, номера ZK не меняются.
  - ИИ (`findExcelTracks`) находит только входящие треки и какой товар к какому треку; остальное — из колонок (`lib/excel-columns.ts`, `actions/excel-row.ts`).
  - Не сохраняется, пока нет клиента («создайте клиента») или получателя у клиента. Получателя можно создать из строки кнопкой «Создать получателя из строки» (ФИО, адрес, телефон, страна — из конца номера строки).
  - Время: заказы — T, задача — T + 10 с, посылка — T + 20 с, «Отправлена» — T + 30 с. T — дата отправки из строки (полдень), если она полная; иначе — момент сохранения.
  - Статус: есть полная дата или номер посылки — «Отправлена», иначе — «Новая». Повторная загрузка статус назад не откатывает, оплаченную посылку не делает неоплаченной.
  - Деньги посылки — из строки: курс (N), отправка (L), скидка (R), стоимость товаров (G), пошлина ЕС — €3 × виды товаров × курс евро (3 × P × O; курса евро нет — из «Финансы»), итого ¥ (S; пусто — по формуле листа), итого $ = итого ¥ ÷ курс. Сверка: итого $ = отправка + услуги, итого ¥ = формула листа — расхождение показывается предупреждением.
  - Услуги: консолидация (J) → «Консолидация», упаковка (K) → «Компактная упаковка», фотоотчёт (I) → «Детальная проверка и фотоотчёт», локальная доставка (Q, ¥) → «Доставка до склада».
  - «+» в оплате (T) — посылка оплачена датой отправки. Номер посылки (U) — трек посылки.
  - Стоимость отправки для нас (V) и выручка (W) — в отдельной таблице `ParcelFinance`: видны только в карточке посылки в админке («Стоимость и выручка»), кабинет клиента её не читает.
  - Клиентам ничего не отправляется; 17TRACK сам подхватит отправленные посылки последних 60 дней по расписанию.
  - Не сделано: сверка цены с тарифом системы по стране (правило 4 — тарифов по стране в базе ещё нет), кнопка в строке Excel (шаг 3).
- **Шаг 3а — файл целиком (2026-10-19).** Решение владельца по пункту 13: оба способа, сначала файл, потом кнопка в строке (кнопка — ссылка HYPERLINK, а в ней не больше 255 символов, поэтому всю строку через неё не передать: кнопка откроет админку, а строку админка возьмёт из скопированного).

  - Файл читает сервер (`app/api/import/excel-file`, `lib/excel-file.ts`, библиотека exceljs): дата-ячейка → «2026.09.20», формула → её значение. Файл не сохраняется, в базу при чтении ничего не пишется.

  - Формула — под «Колонки листа» (кнопка «Скопировать формулу»): `=HYPERLINK("<адрес админки>/import/excel?row="&B2;"Отправить")` — вставить в свободную колонку (X) второй строки и протянуть вниз. Адрес админки формула берёт с открытой страницы, в коде его нет. Разделитель по умолчанию «;» (WPS владельца), можно выбрать «,».

  - В буфере другая строка — подсказка скопировать нужную; браузер не дал прочитать — кнопка «Вставить из буфера» или Ctrl+V в поле (та самая строка разбирается сразу).
  - Строку можно копировать и с колонки A (щелчок по номеру строки): лишние колонки до номера строки отрезаются.

  - Вся строка в ссылку не передаётся: в HYPERLINK не больше 255 символов.

6. **Колонки строки** (замечание владельца): ИИ разбирает только большую ячейку, поэтому вес, фотоотчёт, консолидация, упаковка, стоимость доставки, стоимость отправки, выручка не подтягиваются. Их читать прямо из колонок строки, без ИИ. **Стоимость отправки и выручка — только для сотрудников, в кабинет клиента не попадают никогда.** Подробно — когда дойдём до пункта 6.
   - **Колонки листа** (буквы Excel; строка OG4283AE; ответы владельца 2026-10-19):
     A порядковый номер (не копируется) · B номер строки (`OG4283AE объем`: номер задачи + внутренний комментарий) · C `PL` — колонка LR, система не повторяет · D большая ячейка · E наименования · F количество · G стоимость товаров внутри посылки (30; валюта — $?) · H вес, кг · I фотоотчёт (пусто — нет) · J консолидация, $ · K упаковка, $ · L стоимость отправки, $ (105) · M итого стоимость отправки, $ (107 = 105 + 2) · N курс ¥ за $ (6,80) · O курс евро (7,80) · P количество видов товаров для Европы · Q локальная доставка · R скидка, % · S итого, ¥ (727,60) · T, U — ? (оплата «+», номер посылки?) · V стоимость отправки для нас, ¥ (34; иногда не заполнена) · W выручка, ¥ (693,60 = 727,60 − 34) · X — сюда кнопка «Отправить в базу» (шаг 3) · Y дата отправки · Z получатель · AA адрес · AB телефон · AC–AF — ? · AG–AI части номера (`OG` · `4283` · `AE`).
   - Формула итога в юанях (колонка S): `=M*N + O*P + Q − (M*N + Q)*R%` — итого $ по курсу + курс евро × виды товаров для Европы + локальная доставка − скидка % (на доставку и локальную доставку, не на пошлину).
   - **Пошлина ЕС — €3 за вид товара** (владелец 2026-10-19, ответ «б»): правильно `3 × O × P`, в формуле листа не хватает ×3 → `=M*N+3*O*P+Q-(M*N+Q)*R%`. В системе число видов — поле «Типов товара» в карточке посылки (блок «Таможня ЕС», для стран ЕС); загрузка ставит его из колонки P. Если итог строки посчитан по старой формуле, загрузка покажет предупреждение «Итого ¥ не сходится», а сумму возьмёт из строки.
   - Номера колонок — настройка в базе, а не в коде (правило «система на продажу»): у другой компании колонки другие.
8. **Тариф и сверка цены** (владелец 2026-10-19, «а»): суммы берём из строки как есть; сверку с тарифом системы по стране (правило 4) — позже, когда тарифы по странам будут в базе.
13. **Кнопка в Excel** (владелец 2026-10-19, «в»): оба способа — сначала загрузка файла целиком (сделано, шаг 3а), потом кнопка в строке (колонка X).
