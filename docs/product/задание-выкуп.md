# Задание: «Покупка» — купить и доставить под ключ (FOX2DOOR, ступень 1)

Для рабочего чата «выкуп». **Переделано 2026-11-05** по стратегии FOX2DOOR (`docs/product/FOX2DOOR-стратегия.md`): главный продукт — «под ключ», «только выкуп» — по запросу. Если по прежней версии задания уже что-то сделано — сверить с этой и сказать владельцу, что меняется.

Перед началом прочитать: `AGENTS.md` (правило 6 — система на продажу), `docs/product/документооборот.md` (цепочка документов, нумерация), `docs/product/будущее.md` разделы 0, 3 (включая «Стратегия FOX2DOOR — решено»), 8, `docs/product/FOX2DOOR-стратегия.md` разделы 4, 6, 7.

## Зачем
Клиент нашёл товар в Китае и хочет получить его у двери, не разбираясь в Taobao, Alipay, складе и доставке. Мы покупаем, принимаем, проверяем и отправляем. Цена — прозрачная, по частям.

## Три объекта — не путать (стратегия, 7.3)
1. **Покупка** (новый документ) — корзина из одного или нескольких товаров; трека ещё может не быть.
2. **Заказ `ZK-…`** (есть) — поступление на склад с китайским треком. Один трек — несколько товаров (уже есть).
3. **Посылка `PS-…`** (есть) — международное отправление.

Цепочка: Покупка → заказы `ZK-…` (по трекам продавцов) → задача → посылка. В «Связанных документах» видно всю цепочку.

## Что уже решил владелец
- **Режимы покупки:** «Под ключ» — основной; «Только выкуп» — по запросу, **включается в настройках** (на старте выключен для клиентов, менеджер может выбрать сам).
- **Сайты:** любая ссылка. Обязательно Taobao / Tmall, 1688, Weidian (微店).
- **«По контакту» (WeChat):** вместо ссылки — скриншот, QR или контакт продавца; менеджер договаривается и платит WeChat Pay.
- **Комиссия за покупку: 10% от суммы товара, минимум 10 ¥** — в настройках.
- **Покупают сотрудники** вручную своими аккаунтами. Программа ведёт учёт.
- **Оплата — с баланса клиента.**
- **Копии брендов не выкупаем:** «Отказать» с причиной, среди причин — «подозрение на подделку». Текст правила — в настройках.
- **Возвраты:** брак / не тот товар — за счёт продавца; клиент передумал — за счёт клиента.
- **Россия и Украина** остаются основными направлениями; Европа и США — тоже. Никаких стран в коде — только тарифы из базы.
- **Живёт в нынешнем кабинете.** Свой адрес и вид FOX2DOOR — позже, настройкой компании (бренд из карточки компании, не из кода).

## Что сделать

### 1. Документ «Покупка» — шапка
- Номер по порядку (`lib/document-numbers.ts`), префикс в настройках (по умолчанию `VK-`).
- `companyId` (правило 6). Клиент. Режим (под ключ / только выкуп).
- Для «под ключ»: страна и получатель (из списка получателей клиента), вид доставки, желаемые услуги (консолидация, проверка, упаковка — те же, что у заказа).
- Комментарий клиента, внутренний комментарий, автор, даты, `deletedAt`, история статусов.

### 2. Строки (корзина, как табличная часть в 1С)
- Вид (по ссылке / по контакту), ссылка или вложения, площадка (Taobao, 1688, Weidian, WeChat, другое), продавец, название, вариант (размер, цвет), количество, цена за штуку ¥, доставка по Китаю ¥, фото.
- **Место под автовыкуп:** кто покупает (сотрудник / автомат), номер заказа у продавца, фактически заплачено продавцу.
- Трек продавца. Статус строки (продавцы отправляют в разное время). Ссылка на заказ `ZK-…`.

### 3. Цена — прозрачно, по частям (стратегия, 6)
Клиент видит отдельно: товар, доставка по Китаю, комиссия, **международная доставка — ориентировочно**, услуги, возможные пошлины.
- Ориентировочная доставка: по стране и виду доставки (`findShippingTariff`) и примерному весу (вводит менеджер или клиент). Подпись «ориентировочно, окончательно — после взвешивания». Предварительную цену **не выдавать за окончательную**.
- Если тарифа нет — «рассчитает менеджер».

### 4. Статусы (предложение, владелец может поправить в справочнике статусов)
Покупка: Новая → Цена назначена (ждём клиента) → Оплачена → Выкуплена → На складе (все строки пришли) → Отправлена (есть посылка). Боковые: Отказ (с причиной), Отменена, Возврат.
Строка: Ждёт покупки → Выкуплена → Отправлена продавцом → На складе; Отказ / Возврат.

### 5. Деньги — несколько списаний по одной покупке
- Через `ClientLedger`, новые причины (например «оплата покупки», «возврат по покупке»). Ничего не удаляется — только новые записи.
- Первое списание — за товар + доставку по Китаю + комиссию. Доставка за границу — **как сейчас, после взвешивания посылки**. Возможны доплата и возврат разницы (если продавец поднял цену, часть строк отменена).
- Не хватает баланса — показать, сколько пополнить (заявка на пополнение уже есть).
- Строка «Закупка» в квитанции посылки — из покупок её заказов.
- Правила безопасности денег — раздел 8 `будущее.md`.

### 6. Из покупки — заказы
Менеджер вписал трек продавца → программа сама создаёт заказ `ZK-…` (клиент, получатель, вид доставки, услуги, товары строк с этим треком, цена, ссылка, фото) или добавляет товар в уже созданный заказ с тем же треком. Дальше обычный путь склада.

### 7. Время прохождения (стратегия, 10)
Программа сама сохраняет даты шагов (заявка → цена → оплата → выкуплено → на складе → отправлено) и показывает в карточке, сколько занял каждый шаг. Вручную ничего не заполнять. Отчёт — позже.

### 8. Админка
- Журнал «Покупки» (как другие журналы, `задание-журналы.md`): номер, дата, клиент, режим, строк, итого ¥, статус, страна. Отборы: статус, клиент, режим, период.
- Карточка: шапка, строки, цена по частям, деньги (списания), время шагов, связанные заказы и посылка; кнопки по статусу: «Назначить цену», «Выкуплено», «Вписать трек», «Отказать (причина)», «Возврат».
- Настройки: режим «Только выкуп» для клиентов вкл/выкл, комиссия %, минимум, префикс, причины отказа, текст правила о копиях брендов.

### 9. Кабинет клиента
- На главной кабинета — **две большие кнопки: «Хочу купить» и «Я уже купил»**. «Я уже купил» ведёт в существующее добавление заказа с треком (`app/cabinet/new`) — его не переделывать.
- «Хочу купить»: корзина — вставить ссылку или вложить скриншот, вариант, количество; страна и получатель; ориентировочная цена по частям.
- «Мои покупки»: что произошло / что происходит / **что нужно от меня** / сколько заплатить. Кнопка «Оплатить с баланса», когда цена назначена.
- Клиент видит только свои покупки.

### 10. Оповещения
- Владельцу (`notifyOwner`): новая покупка, клиент оплатил.
- Клиенту (Telegram, как у посылок): цена назначена, выкуплено, товар на складе, отказ с причиной.

## Границы
- Кабинет ведёт чат «кабинет клиента». Новые страницы — в своей папке (`app/cabinet/purchases`); в общих файлах (главная, меню) — только кнопки и ссылка, и сказать об этом владельцу.
- Не трогать работу чатов «админка», «кабинет клиента», «контент».
- Без автоматической покупки, без подтягивания карточки товара по ссылке, без поиска по Taobao — это следующие ступени. Только места под них.
- Без отдельного адреса FOX2DOOR — позже.
