# Задание: выкуп товара за клиента (ступень 1)

Для нового рабочего чата «выкуп». Решения владельца — `docs/product/будущее.md`, раздел 3. Порядок направлений (2026-11-02): **сначала выкуп**, потом FOX2DOOR (выкуп + отправка «под ключ»). FOX2DOOR в это задание не входит.

Перед началом прочитать: `AGENTS.md` (правило 6 — система на продажу), `docs/product/документооборот.md` (цепочка документов, нумерация), `docs/product/будущее.md` разделы 0, 3, 8.

## Зачем
Клиент не может сам купить в Китае: язык, Alipay, продавец не везёт за границу. Мы покупаем за него, товар приходит на наш склад и дальше идёт обычным путём: заказ `ZK-…` → задача → посылка.

## Что уже решил владелец
- **Сайты:** любая ссылка клиента. Обязательно Taobao / Tmall, 1688, Weidian (微店). Pinduoduo, Poizon, JD — позже, но ссылку принимаем любую.
- **Комиссия: 10% от суммы товара, минимум 10 ¥.** Процент и минимум — в настройках, не в коде.
- **Цена для клиента** = товар + доставка по Китаю до склада + комиссия, в юанях.
- **Покупают сотрудники** в Гуанчжоу со своими аккаунтами Taobao / Alipay — вручную. Программа только ведёт учёт.
- **Оплата — с баланса клиента:** сначала пополнение, потом оплата выкупа.
- **«Закупка по контакту» (WeChat):** вместо ссылки клиент прикладывает скриншот, QR-код или контакт продавца (朋友圈, 小程序). Менеджер договаривается и платит через WeChat Pay. Комиссия та же.
- **Копии брендов не выкупаем.** У менеджера кнопка «Отказать» с причиной; среди причин — «подозрение на подделку». Текст правила — в условиях сервиса (настройки), не в коде.
- **Возвраты:** брак или не тот товар — за счёт продавца, мы оформляем возврат; клиент передумал — за счёт клиента (доставка продавцу и комиссия).

## Что сделать

### 1. Документ «Выкуп» (новая таблица)
- Номер по порядку через `lib/document-numbers.ts`, префикс в настройках (предложение: `VK-`).
- `companyId` — чья компания (правило 6).
- Клиент, вид заявки (**по ссылке** / **по контакту**), ссылка или вложения (скриншот, QR), название товара, вариант (размер, цвет), количество, комментарий клиента, внутренний комментарий.
- Деньги в ¥: цена товара, доставка по Китаю, комиссия (считается по настройкам, менеджер может поправить с отметкой), итого. Фактически заплачено продавцу (для учёта нашей разницы).
- Трек-номер продавца; ссылка на заказ `ZK-…`, созданный из выкупа.
- Статус и история статусов, автор, даты, `deletedAt`.

### 2. Статусы (предложение, владелец может поправить)
Новая → Цена назначена (ждём клиента) → Оплачена → Выкуплена → Отправлена продавцом (есть трек) → На складе.
Боковые: Отказ (с причиной), Отменена клиентом, Возврат.
Названия статусов — в справочнике статусов, как у заказов и посылок.

### 3. Деньги
- Оплата выкупа списывает с баланса через `ClientLedger` (новая причина, например «оплата выкупа»); отказ / отмена / возврат — обратная запись. Ничего не удаляется, только новые записи.
- Списать можно, только если хватает баланса. Не хватает — клиенту показываем, сколько пополнить (существующая заявка на пополнение).
- Строка «Закупка» в квитанции посылки — из выкупов её заказов.
- Правила безопасности денег из раздела 8 `будущее.md` соблюдать.

### 4. Из выкупа — заказ
Когда менеджер вписал трек продавца, программа сама создаёт заказ `ZK-…` (клиент, товар, количество, цена, ссылка, фото, трек) и связывает его с выкупом. Дальше обычный путь склада. В «Связанных документах» видно: выкуп → заказ → задача → посылка.

### 5. Админка
- Журнал «Выкупы» (раздел по меню — как у других журналов, см. `задание-журналы.md`): номер, дата, клиент, вид, товар, итого ¥, статус, трек, заказ. Отборы: статус, клиент, период.
- Карточка выкупа: все поля, вложения, кнопки по статусу — «Назначить цену», «Выкуплено», «Вписать трек», «Отказать (причина)», «Возврат».
- Настройки: процент комиссии, минимум, префикс номера, причины отказа, текст правила о копиях брендов.

### 6. Кабинет клиента
- Новая страница «Выкуп»: форма «вставить ссылку» и «по контакту» (вложить скриншот / QR), вариант, количество, комментарий.
- Список своих выкупов со статусами; кнопка «Оплатить с баланса», когда цена назначена.
- Клиент видит только свои выкупы.

### 7. Оповещения
- Владельцу (`notifyOwner`): новая заявка на выкуп, клиент оплатил.
- Клиенту (Telegram, как у посылок): цена назначена, выкуплено, товар на складе, отказ с причиной.

## Границы
- Кабинет клиента ведёт отдельный чат «кабинет клиента». Новые страницы выкупа делать в своей папке (`app/cabinet/buyouts`), в общих файлах кабинета — только ссылка в меню; если меняются общие файлы — сказать владельцу.
- Чужую текущую работу чатов «админка» и «кабинет клиента» не трогать.
- Без автоматической покупки, без парсинга карточек товара (это ступень 2), без поиска по Taobao (ступень 3).

## Как сдать
- Можно разбить на 2–3 PR: (1) таблица, статусы, настройки, журнал и карточка в админке; (2) кабинет клиента и оплата с баланса; (3) создание заказа и оповещения.
- К каждой части — короткая инструкция для владельца (`docs/product/инструкция-выкуп.md`).
- Проверить на клиенте `ABC`: заявка по ссылке Taobao → цена → оплата с баланса → выкуплено → трек → заказ `ZK-…`; заявка по контакту; отказ «подозрение на подделку» с возвратом денег на баланс; нехватка баланса.
