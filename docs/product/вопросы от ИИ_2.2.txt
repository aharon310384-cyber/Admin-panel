ЧАСТЬ I. ОБНОВЛЁННОЕ ПОНИМАНИЕ (подтверди / поправь)
═══════════════════════════════════════════════════════════════
•1 ЗАКАЗ = СТРОКА = ТОВАР — одна сущность (1 товар + 1 трек). Трек-номер — поле строки, НЕ уникален (может повторяться).
•2 Строки группируются → в ПОСЫЛКУ (документ с номером, ген. при оформлении на отправку).
•3 При ОФОРМЛЕНИИ посылки строки-заказы УХОДЯТ в посылку и ИСЧЕЗАЮТ из активного списка клиента → клиент дальше следит за статусом ПОСЫЛКИ.
•4 Расформировать посылку можно, только пока статус «Новый» (до «Собран»). После «Собран»/выше — клиент не может.
•5 СТАТУСЫ заказа/строки: Новый → В очереди на приём → Принят на склад (или «Принят с несоответствием») → Оформлена на отправку → Собран → Упакован → Отправлена → Доставлена → (Возвращён).
•6 Посылка готова к сборке, когда у ВСЕХ её заказов статус «Принят на склад».
•7 В посылку берутся строки статусов: Новый, В очереди на приём, Принят на склад.
•8 АРМ «Приём заказа» + АРМ «Потеряшка» (отдельный регистр: трек/вес/ИД клиента/примечание/фото/дата/автор; статусы Потеряшка→Передано на приём→Утилизировано) — ПОТОМ.
•9 Роли (складской работник) — ПОТОМ.
•10 ИИ-обработчик: вход = текст заявки клиента / Excel → извлекает товары/треки/кол-во/цены/получателя → ЧЕРНОВИК на подтверждение менеджером.
•11 Декларация на уровне СТРОКИ: HS-код + категория + объявленная стоимость (=цена×кол-во). Согласовано.
•12 ПОЛУЧАТЕЛЬ — отдельная таблица Recipient (связь на клиента). Создам/переделаю.
•13 Услуги — строками в посылке (название+цена), + СКИДКИ фиксируем. Квитанция = документ (кнопка печати).
•14 Упаковка может добавляться при оформлении по стране (EMS = полная переупаковка) → нужен справочник упаковки.
•15 Оплата: ТОЛЬКО за доставку (системы закупки нет), валюта CNY, курс вручную фиксируется при оплате. Статус «Оформлена посылка» — после взвешивания. Отправка — после оплаты.
•16 Самовывоз = клиент сам забирает со склада (это возврат, но клиент сам, не мы магазину) → статус «Возвращён».
•17 Тарифы — справочник в БД (+ кнопка печати квитанции). Расчётный вес = фактический, но менеджер может перебить вручную.
•18 Уведомления: Telegram, событие «нужна оплата», текст должен быть аккуратным (не пугать).
•19 На будущее: интеграции с другими системами; вход через WeChat (Y2) и докрутка Telegram-входа (Y3).
