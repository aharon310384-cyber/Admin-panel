ЧАСТЬ IV. ОТЛОЖЕННЫЕ ЗАДАЧИ — РАЗВЁРНУТО (ты просил расписать, чтобы не забыть)
═══════════════════════════════════════════════════════════════
1) ДЕЛИТЕЛЬ ОБЪЁМНОГО ВЕСА.
   Объёмный вес = Д×Ш×В(см) / делитель. Делитель зависит от вида доставки (авиа ~5000, курьер ~6000, возможно 168 для иных). ГДЕ: поле «делитель» в справочнике тарифов. КОГДА: определить значения делителей по направлениям → добавить расчёт объёмного веса в карточку строки/посылки.

2) ПОТЕРЯШКА (регистр + АРМ).
   Отдельная таблица: трекномер, вес, ИД клиента, примечание, фото-ссылка, дата, автор (авто). Статусы: Потеряшка → Передано на приём → Утилизировано. АРМ «Потеряшка» — экран склада. СОЗДАЁТСЯ когда на склад пришёл трек, которого нет в системе. ГДЕ: новый раздел «Потеряшки» в админке + кнопка в АРМ приёмки «оформить как потеряшку».

3) ВЫКУПЫ ИЗ МАРКЕТПЛЕЙСОВ / WECHAT (= оплата за товар).
   Модуль закупки: менеджер/система выкупает товар у поставщика за клиента. Появляется оплата ЗА ТОВАР (китайская цена), отдельно от доставки. Строки «Закупка»/«Дост до склада» в квитанции оживут. ГДЕ: новый модуль «Выкуп», связь со строкой-заказом, отдельный платёж.

4) ТАМОЖЕННЫЕ ЛИМИТЫ ПО СТРАНАМ.
   В справочник стран — лимит беспошлинного ввоза (сумма/вес). При оформлении посылки система предупреждает, если объявленная стоимость превышает лимит страны получателя. ГДЕ: поле лимита в Country + проверка при оформлении.

5) ПЕРЕИМЕНОВАНИЕ СТАТУСОВ.
   Финальные пользовательские названия статусов (RU, возможно EN/CN для клиента). Отдельная сессия — когда устаканится процесс.

6) АРХИТЕКТУРА CRM (менеджер) / ERP (склад).
   Разделение рабочих мест: CRM — клиенты, заказы, расчёты, оплаты, общение (менеджер); ERP/WMS — приёмка, сборка, упаковка, отправка (склад). Возможно разные интерфейсы под роли. ГДЕ: после ядра — спроектировать два рабочих пространства.

7) РОЛИ СКЛАДСКИХ РАБОТНИКОВ.
   Добавить роль WAREHOUSE (склад) в enum UserRole. Права: АРМ приёмки, сборка, упаковка; без доступа к финансам/клиентам. ГДЕ: расширить UserRole + проверки прав.

8) ВХОД ЧЕРЕЗ WECHAT (Y2).
   Аналог Telegram-привязки, но через WeChat (Mini Program getPhoneNumber / OAuth). Поля Customer.wechat*. Блокер — регистрация WeChat Mini Program. ГДЕ: после релиза, повторить Telegram-схему.

9) ВАРИАНТЫ «1 ТРЕК = МНОГО КОРОБОК / ДЕЛЕНИЕ».
   При приёмке: 1 трек = 1 коробка = 1 строка; 1 трек = много коробок; 1 трек = 1 коробка делится на много строк. Логика приёмки и привязки коробок к строкам. ГДЕ: в АРМ приёмки — обработка многокоробочных треков.

10) ИНТЕГРАЦИИ С ВНЕШНИМИ СИСТЕМАМИ.
   Ты планируешь интеграции. УТОЧНИТЬ: с какими системами (1С? курьерские API? маркетплейсы? бухгалтерия?) — чтобы заложить API/совместимость заранее.
