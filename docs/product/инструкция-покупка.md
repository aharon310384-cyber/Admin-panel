# Покупка под ключ (FOX2DOOR, ступень 1): как работает

Коротко для владельца и сотрудников. Задание — `docs/product/задание-выкуп.md`, стратегия — `docs/product/FOX2DOOR-стратегия.md`. Сделано 2026-11-05.

Где: в админке — раздел **Покупки** (журнал «Покупки», «Настройки покупки») и **Финансы → Заявки на пополнение**. В кабинете клиента — две большие кнопки на главной: **«Хочу купить»** и **«Я уже купил»**; «Мои покупки» — в меню (на телефоне — «Ещё»).

Не путать три вещи: **покупка** (`VK-…`) — что купить, корзина товаров; **заказ** (`ZK-…`) — товар, пришедший на склад с китайским треком; **посылка** (`PS-…`) — международное отправление. Покупка → заказы по трекам продавцов → задача → посылка.

## Путь покупки
1. **Клиент:** «Хочу купить». В корзине — один или несколько товаров:
   - **Ссылка** — Taobao / Tmall, 1688, Weidian или любой сайт; можно вставить весь текст из «Поделиться», ссылку программа найдёт сама;
   - **Продавец в WeChat** — контакт и/или скриншот, QR-код;
   - что за товар, вариант (размер, цвет), количество, цена за штуку — если клиент её знает.
   Для «под ключ» — страна, вид доставки, получатель из своих, примерный вес, услуги склада. Пока клиент заполняет, справа **ориентировочная цена по частям**: товар, доставка по Китаю («назовёт менеджер»), комиссия, доставка за границу по тарифу и весу, услуги, возможная пошлина. Подпись: «не окончательная цена». Нет тарифа в эту страну — «рассчитает менеджер».
   Владельцу — оповещение «Новая покупка».
2. **Менеджер:** журнал → покупка → **«Назначить цену»**: цена и доставка по Китаю у каждой строки, площадка, продавец; при необходимости — режим, страна, вид доставки, получатель, вес, услуги. Комиссия считается сама (10%, не меньше 10 ¥); «Поправить комиссию вручную» — с отметкой. Ориентировочная доставка за границу пересчитывается при сохранении. Клиенту — сообщение с ценой.
3. **Клиент** в «Мои покупки» видит у каждой покупки: **что произошло**, **что происходит**, **что нужно от вас**, **сколько заплатить**. Цена назначена — «Оплатить с баланса». Не хватает — «Пополнить на ¥…» (заявка на пополнение: сумма, способ, номер платежа, скриншот).
4. **Администратор** зачисляет пополнение: «Финансы → Заявки на пополнение» → «Зачислить» (номер платежа, пароль).
5. **Сотрудник** покупает и в строке нажимает **«Выкуплено»** (сколько заплатил продавцу, номер заказа у продавца). Все строки выкуплены — покупка «Выкуплена».
6. Продавец отправил — в строке **«Вписать трек»**. Программа сама создаёт **заказ ZK-…**: клиент, получатель, вид доставки и услуги — из покупки; товар, количество, цена, ссылка, фото и трек — из строки. Две строки с одним треком — два заказа одного трека, склад примет их одной коробкой. Дальше — обычный путь склада.
7. Склад принял все заказы — покупка «На складе». Заказы оформили в посылку — «Отправлена». Международную доставку клиент платит **как сейчас — после взвешивания посылки**.

В карточке — **время прохождения**: заявка → цена → оплата → выкуплено → на складе → отправлено, сколько занял каждый шаг и сколько идёт текущий. Даты пишет программа сама. «Связанные документы» (Ctrl+Shift+S): покупка → её деньги → заказы → задача → посылка. В квитанции посылки — строка **«Закупка — покупка VK-…»** для сведения: клиент уже заплатил с баланса, в ИТОГО она не входит.

## Деньги — несколько списаний по одной покупке
- Первое списание — товар + доставка по Китаю + комиссия.
- Продавец поднял цену — менеджер меняет цену строки (пока она не выкуплена) → клиенту «Доплатить ¥…» и сообщение. Покупать строку до доплаты программа не даст.
- Цена упала или строку отменили — разница **сама** возвращается на баланс.
- Всё пишется в регистр «Изменение долга клиента» (DK-…): «Оплата покупки», «Возврат по покупке», «Возврат товара». Записи не удаляются.

## Отказ и возврат
- **Отказать по строке** (товара нет, продавец не отвечает, подделка) — до трека. Строка уходит из цены, деньги за неё — на баланс.
- **Отказать — вся покупка** — пока ни по одной строке нет заказа. Оплачено — всё на баланс. Среди причин — «Подозрение на подделку»; правило о копиях брендов — в условиях сервиса.
- **Клиент отменяет** сам — до оплаты.
- **Возврат** по строке — после «Выкуплено»: брак / не тот товар — за счёт продавца (клиенту стоимость строки); клиент передумал — за его счёт (товар минус доставка продавцу; комиссия и доставка по Китаю не возвращаются). Сумму можно поправить, но не больше стоимости строки. Заказ строки — «Возвращён». Заказ уже в посылке — сначала убрать его из посылки.

## Режимы
- **Под ключ** — основной: купить, принять, проверить и отправить.
- **Только выкуп** — купить и принять на склад, посылку клиент оформит сам. Клиенту доступен, только если в настройках включено «Клиент может выбрать „Только выкуп“» (на старте выключено). Менеджер может выбрать режим в карточке всегда.

## Настройки (Покупки → Настройки покупки)
Свои у компании клиентов (чей бренд в кабинете). Заполняются при обновлении решениями владельца, дальше — только здесь: «Только выкуп» для клиентов, комиссия % и минимум (10% и 10 ¥), префикс номера (VK), причины отказа, условия сервиса, способы оплаты, **реквизиты для оплаты — вписать**, порог пароля при зачислении.

## Безопасность денег (будущее.md, раздел 8)
Зачисляет только администратор; номер платежа обязателен и зачисляется один раз; пароль — выше порога (порог пуст — всегда); ошибка — «Сторно» (обратная запись); клиенту — сообщение о каждом зачислении, списании, возврате; два одновременных списания не уведут баланс в минус.

## Что сделать владельцу после обновления
1. «Покупки → Настройки покупки»: проверить комиссию и условия, вписать реквизиты для оплаты; решить, показывать ли клиентам «Только выкуп».
2. «Логистика → Тарифы»: у нужных стран (Россия, Украина, Европа, США) — действующие тарифы, иначе ориентировочная доставка будет «рассчитает менеджер».
3. «Настройки → Оповещения владельцу» — включены.

## Решения чата «выкуп» (можно поправить)
- «Заказ = товар»: одна строка покупки — один заказ; строки с одним треком — заказы одной коробки (так уже работает «один трек — несколько товаров»).
- Ориентировочная доставка — по тарифу страны и вида доставки × примерный вес (с минимальным весом тарифа); услуги — по ценам услуг; пошлина ЕС — €3 за вид товара, если товар дешевле €150. Для других стран — подпись о лимите страны.
- «На складе» и «Отправлена» подтягиваются, когда открывают журнал, карточку или «Мои покупки»: приём на склад и оформление посылки — работа чата «админка», их код не трогал.
- Действия в админке — у администратора (как везде в программе).
- Скриншоты и QR клиентов — в `data/uploads/purchases`, видны только сотрудникам и самому клиенту. Эту папку стоит добавить в резервные копии.

## Для разработчиков
- Таблицы: `Purchase` (шапка), `PurchaseLine` (строки, место под автовыкуп: `buyer`, `sellerOrderNo`, `paidToSellerCny`), `PurchaseStatusHistory`, `PurchaseSettings` — у шапки и настроек есть компания. `ClientLedger` + `purchaseId`, `paymentId`, причины `TOP_UP`, `PURCHASE_PAYMENT`, `PURCHASE_REFUND`, `PURCHASE_RETURN`; `TopUpRequest` + способ, номер платежа, скриншот; `Payment.reference`. Обновление: `npx prisma db push` (без потери данных) и `npm run db:upgrade:purchases` (входит в `db:upgrade`).
- Код: `lib/purchases.ts` (настройки, пересчёт денег и статуса — `settlePurchase`, подтяжка «На складе» — `syncPurchases`), `lib/purchase-estimate.ts`, `lib/purchase-money.ts`, `lib/purchase-lines.ts`, `lib/purchase-order.ts`, `lib/purchase-notify.ts`, `lib/purchase-options.ts`, `lib/purchase-files.ts`, `lib/balance.ts`; действия `actions/purchases.ts`, `actions/purchase-cabinet.ts`, `actions/top-ups.ts`, `actions/purchase-settings.ts`; экраны `app/(admin)/purchases`, `app/(admin)/top-ups`, `app/cabinet/purchases`; файлы `app/api/purchases/files`.
- Общие файлы (по 1–3 строки): главная кабинета `app/cabinet/page.tsx` — две кнопки (`app/cabinet/purchases/_components/start-buttons.tsx`); меню кабинета (`cabinet-sidebar.tsx`, `cabinet-nav.tsx`, `app/cabinet/more/page.tsx`); меню админки (`lib/interface.ts`, `topnav.tsx`); связанные документы (`lib/related.ts`, `lib/related-documents.ts`, страница `related`); квитанция посылки (`app/(admin)/parcels/[id]/page.tsx`); `lib/statuses.ts`, `lib/document-numbers.ts` (префикс из настроек), `package.json`, `.gitignore`.
- **Для чата «админка»:** после приёма коробки (`receiveBox`) и оформления посылки можно вызвать `syncPurchases()` — тогда «На складе» / «Отправлена» и сообщение клиенту будут сразу, а не при открытии экранов.
- **Для чата «кабинет клиента»:** страницы покупки — в `app/cabinet/purchases`; на главной — только две кнопки. Строку «Закупка» в квитанцию посылки кабинета можно добавить так же, как в админке (`components/purchases/parcel-purchase-rows.tsx`).
