# Выкуп товара за клиента: как работает

Коротко для владельца и сотрудников. Задание — `docs/product/задание-выкуп.md` (ступень 1). Сделано 2026-11-02.

Где: в админке — раздел **Выкуп** (журнал «Выкупы», «Настройки выкупа») и **Финансы → Заявки на пополнение**. В кабинете клиента — **Выкуп** (в боковом меню, на телефоне — «Ещё» → «Выкуп»).

## Путь выкупа
1. **Клиент** в кабинете: «Выкуп» → «Новая заявка».
   - **По ссылке** — вставляет ссылку или весь текст из «Поделиться» (Taobao / Tmall, 1688, Weidian, любой сайт): программа сама достанет ссылку из текста.
   - **По контакту** — продавец в WeChat: скриншот товара, QR-код продавца и/или его контакт.
   - Пишет, что за товар, вариант (размер, цвет), количество, комментарий. Внизу формы — условия сервиса из настроек.
   - Владельцу приходит оповещение «Новая заявка на выкуп».
2. **Менеджер** открывает выкуп (журнал → строка) и нажимает **«Назначить цену»**: цена за штуку, количество, доставка по Китаю до склада. Комиссия считается сама по настройкам (10%, не меньше 10 ¥); галочка «Поправить комиссию вручную» — если нужно иначе, в карточке будет отметка «поправлена вручную». Клиенту — сообщение с ценой. Пока клиент не оплатил, цену можно поменять.
3. **Клиент** видит цену: товар + доставка по Китаю + комиссия, итого в юанях.
   - Денег хватает — кнопка **«Оплатить с баланса»**. Деньги списываются, владельцу — оповещение «Клиент оплатил выкуп».
   - Не хватает — кнопка **«Пополнить на ¥…»**: страница «Баланс» с этой суммой. Клиент платит по реквизитам из настроек и отправляет заявку на пополнение: сумма, способ, номер платежа, скриншот.
4. **Администратор** проверяет оплату: **Финансы → Заявки на пополнение** → заявка → **«Зачислить»** (сколько пришло, номер платежа, свой пароль). Клиенту — сообщение «Зачислено». Неверная заявка — «Отклонить» с причиной.
5. **Сотрудник** покупает товар своим аккаунтом Taobao / Alipay / WeChat Pay и нажимает **«Выкуплено»** — можно сразу вписать, сколько фактически заплачено продавцу (видно «наша разница»).
6. Продавец отправил — **«Вписать трек»**. Программа сама создаёт заказ **ZK-…** (клиент, товар, количество, цена, ссылка, фото товара, трек), выкуп — «Отправлена продавцом». Дальше обычный путь склада.
7. Склад принял заказ — у выкупа **«На складе»**, клиенту сообщение.

«Связанные документы» в карточке выкупа (Ctrl+Shift+S): выкуп → его деньги → заказ → задача → посылка. В квитанции посылки — строка **«Закупка — выкуп VK-…»**: сумма для сведения, в ИТОГО посылки не входит (клиент уже заплатил с баланса).

## Отказ, отмена, возврат
- **Отказать (причина)** — пока заказа ещё нет (новая, цена назначена, оплачена, выкуплена). Причины — из настроек, среди них «Подозрение на подделку»; можно написать свою. Если клиент уже заплатил — вся сумма возвращается на баланс.
- **Клиент отменяет** сам — только до оплаты. После оплаты — через менеджера («Отказать»).
- **Возврат** — после «Выкуплено»:
  - брак или не тот товар — за счёт продавца: клиенту на баланс всё;
  - клиент передумал — за счёт клиента: программа предлагает «товар минус доставка продавцу» (комиссия и доставка по Китаю не возвращаются), сумму можно поправить.
  - Заказ из выкупа получает статус «Возвращён». Если заказ уже в посылке — сначала уберите его из посылки.
- Удалить выкуп нельзя, только **пометить на удаление** — и только новый, неоплаченный, отклонённый или отменённый.

## Деньги и безопасность
Баланс клиента — его деньги у нас, в юанях. Каждое движение — запись в регистре «Изменение долга клиента» (DK-…): пополнение, оплата выкупа, возврат. Записи не правятся и не удаляются.
- Зачисляет **только администратор** (отдельного права «деньги» пока нет — это роль «Администратор»).
- **Номер платежа** обязателен; один номер второй раз не зачислится. Скриншот и номер — в заявке.
- Пароль при зачислении: сумма больше порога из настроек — пароль; порог не задан — пароль всегда.
- Ошибка — **«Сторно»** в зачисленной заявке (с паролем): обратная запись на ту же сумму, приход ДС — с пометкой удаления. Если клиент уже потратил деньги, баланс уйдёт в минус.
- Клиенту — сообщение в Telegram о каждом зачислении, списании, возврате и сторно (если Telegram привязан; в карточке выкупа видно, если нет).
- Списание: два одновременных нажатия «Оплатить» не спишут дважды и не уведут баланс в минус.

## Настройки (Выкуп → Настройки выкупа)
Свои у компании клиентов (чей бренд в кабинете). При обновлении программы заполняются решениями владельца, дальше меняются только здесь:
- комиссия, % от суммы товара, и минимум, ¥ (сейчас 10% и 10 ¥);
- префикс номера (VK → VK-000001);
- причины отказа (по одной в строке);
- условия сервиса — клиент видит их в форме заявки (правило о копиях брендов, возвраты);
- способы оплаты (WeChat Pay, Alipay, банковский перевод, карта, USDT), реквизиты «куда платить» — **заполнить**, сейчас пусто, клиенту написано «реквизиты пришлёт менеджер»;
- порог суммы, выше которой зачисление — с паролем (пусто — пароль всегда).

## Что сделать владельцу после обновления
1. «Выкуп → Настройки выкупа» — проверить комиссию и условия, вписать **реквизиты для оплаты**.
2. «Настройки → Оповещения владельцу» — должны быть включены (туда придут новые заявки, оплаты и пополнения).

## Решения, которые принял чат «выкуп» (можно поправить)
- Статусы — как в задании. Отдельной кнопки «На складе» нет: статус ставится сам, когда склад принял заказ.
- Отказ возможен до создания заказа (в том числе после «Выкуплено», например продавец отменил); после трека — только «Возврат».
- Пополнение баланса сделано здесь же, минимально (заявка клиента → «Зачислить» → сторно), потому что без него оплата с баланса не работает. Журналы «Приход ДС» и «Изменение долга клиента» — по плану журналов, позже.
- Действия с выкупом в админке — у администратора (как и остальные изменения в программе); менеджер видит.
- Скриншоты и QR-коды клиентов лежат не в общей папке картинок, а в `data/uploads/buyouts` — их видят только сотрудники и сам клиент. Копию этой папки стоит добавить в резервные копии вместе с базой.

- Общие файлы, которые пришлось тронуть (по одной-две строки): меню админки (`lib/interface.ts`, `components/layout/topnav.tsx`), меню кабинета (`components/cabinet/cabinet-sidebar.tsx`, `cabinet-nav.tsx`, `app/cabinet/more/page.tsx`), связанные документы (`lib/related.ts`, `lib/related-documents.ts`, страница `related`), квитанция посылки (`app/(admin)/parcels/[id]/page.tsx` — строка «Закупка»), `lib/statuses.ts`, `lib/document-numbers.ts` (префикс из настроек), `package.json`, `.gitignore`.
- **Для чата «админка»:** приём на склад (`actions/order-receive.ts`) сейчас переделывается, поэтому «На складе» подтягивается при открытии журнала, карточки и кабинета (`syncBuyoutsAtWarehouse`). Когда приём будет готов, после приёма коробки можно вызвать `syncBuyoutsAtWarehouse()` — тогда сообщение клиенту уйдёт сразу.
- **Для чата «кабинет клиента»:** страницы выкупа — в `app/cabinet/buyouts`; в общих файлах кабинета — только пункт меню. Квитанцию посылки в кабинете (`app/cabinet/parcels/[id]`) не трогал: строку «Закупка» туда можно добавить так же, как в админке (`components/buyouts/parcel-purchase-rows.tsx`).
