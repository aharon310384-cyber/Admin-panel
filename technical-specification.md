# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Разработка Админ-панели для управления интернет-магазином

**Версия:** 1.0  
**Дата:** 2026-04-23  
**Статус:** Черновик

---

## 1. ОБЩИЕ СВЕДЕНИЯ

### 1.1 Наименование системы
Административная панель управления интернет-магазином (далее — Система).

### 1.2 Цель разработки
Создать веб-приложение для внутреннего использования, позволяющее сотрудникам магазина управлять заказами, клиентами и каталогом товаров без технических знаний.

### 1.3 Основание для разработки
Существующий стартовый шаблон на Next.js + Prisma + PostgreSQL (см. `research.md`, `idea.md`).

---

## 2. ТРЕБОВАНИЯ К СИСТЕМЕ

### 2.1 Функциональные требования

#### 2.1.1 Авторизация
- Вход по email и паролю
- Хранение сессии через JWT (NextAuth.js)
- Выход из системы
- Защита всех страниц кроме `/login` через middleware
- Две роли пользователей:
  - **Администратор** — полный доступ ко всем разделам
  - **Менеджер** — доступ только к заказам и клиентам

#### 2.1.2 Dashboard (главная страница)
- Отображение реальных метрик из БД:
  - Количество новых заказов за сегодня
  - Выручка за текущую неделю
  - Количество активных клиентов
- График заказов за последние 7 дней
- Топ-5 товаров по количеству продаж
- Таблица последних 10 заказов

#### 2.1.3 Управление заказами
- Список всех заказов с пагинацией (20 записей на страницу)
- Фильтрация по:
  - Статусу (NEW, PROCESSING, SHIPPED, COMPLETED, CANCELED)
  - Диапазону дат
  - Диапазону суммы
- Поиск по номеру заказа и имени клиента
- Детальная страница заказа:
  - Информация о клиенте
  - Список товаров в заказе (название, количество, цена)
  - Итоговая сумма
  - История изменений статуса с датами
  - Поле заметок
- Смена статуса заказа
- Мягкое удаление заказа (soft delete)
- Экспорт списка заказов в CSV

#### 2.1.4 Управление клиентами
- Список клиентов с пагинацией (20 записей на страницу)
- Поиск по имени, email, городу
- Сортировка по дате регистрации и сумме покупок
- Карточка клиента:
  - Контактные данные (имя, email, телефон, город)
  - Статистика: количество заказов, общая сумма покупок
  - История всех заказов клиента
- Редактирование данных клиента
- Мягкое удаление клиента (soft delete)

#### 2.1.5 Управление товарами
- Список товаров с пагинацией (20 записей на страницу)
- Фильтрация по: статусу активности, наличию на складе
- Поиск по названию, SKU, slug
- Создание нового товара:
  - Название, slug (автогенерация из названия), SKU
  - Описание
  - Цена
  - Количество на складе
  - Загрузка изображения
  - Статус активности
- Редактирование товара
- Архивация товара (isActive = false)
- Мягкое удаление товара (soft delete)
- Запрет удаления товара, если он присутствует в заказах

#### 2.1.6 Настройки
- Смена пароля текущего пользователя
- Просмотр информации об аккаунте

---

### 2.2 Нефункциональные требования

#### 2.2.1 Производительность
- Время загрузки страниц — не более 2 секунд
- Пагинация во всех списках (не более 20 записей за запрос)
- Индексы в БД на полях фильтрации и поиска

#### 2.2.2 Безопасность
- Все пароли хранятся в зашифрованном виде (bcrypt)
- Защита от XSS — экранирование пользовательского ввода
- Валидация входных данных на сервере (Zod)
- Доступ к API только для авторизованных пользователей
- CSRF-защита через NextAuth.js

#### 2.2.3 Удобство использования
- Адаптивный интерфейс (десктоп + планшет)
- Toast-уведомления при успешных/ошибочных действиях
- Подтверждение перед удалением (модальное окно)
- Валидация форм с понятными сообщениями об ошибках

## 4. СТРУКТУРА РОУТОВ

```

/dashboard                    — аналитика и метрики

/settings                     — настройки аккаунта

/api/auth/[...nextauth]       — NextAuth endpoints
/api/orders                   — GET (список), POST (создать)
/api/orders/[id]              — GET, PATCH (обновить), DELETE
/api/customers                — GET (список)
/api/customers/[id]           — GET, PATCH, DELETE
/api/products                 — GET (список), POST (создать)
/api/products/[id]            — GET, PATCH, DELETE
/api/upload                   — POST (загрузка изображения)
/api/export/orders            — GET (экспорт CSV)
/api/health                   — GET (проверка доступности)
```

## 5. МОДЕЛИ ДАННЫХ

### Существующие модели (оставить без изменений)
- `Customer` — клиенты
- `Product` — товары
- `Order` — заказы
- `OrderItem` — позиции заказа
- `OrderStatus` — enum статусов

### Новые модели

#### User (Пользователь системы)
```
- id          String    — CUID
- email       String    — уникальное
- password    String    — bcrypt hash
- name        String
- role        UserRole  — enum (ADMIN, MANAGER)
- createdAt   DateTime
- updatedAt   DateTime
- deletedAt   DateTime? — soft delete
```

#### UserRole (Enum)
```
- ADMIN    — администратор
- MANAGER  — менеджер
```

#### OrderStatusHistory (История статусов заказа)
```
- id        String    — CUID
- orderId   String    — FK
- status    OrderStatus
- changedBy String    — FK → User.id
- note      String?
- createdAt DateTime
```

## 8. ЭТАПЫ РАЗРАБОТКИ

### Этап 1 — Авторизация (Приоритет: Высокий)
- Установка и настройка NextAuth.js с Prisma Adapter
- Миграция: добавление моделей `User`, `UserRole`, `OrderStatusHistory`
- Страница `/login`
- Middleware для защиты роутов
- Логика разграничения прав по роли

### Этап 2 — Заказы (Приоритет: Высокий)
- Server Actions для CRUD операций
- Страница `/orders` с фильтрами, поиском, пагинацией
- Страница `/orders/[id]` с деталями и историей статусов
- Смена статуса заказа
- Экспорт в CSV

### Этап 3 — Клиенты (Приоритет: Высокий)
- Страница `/customers` с поиском и пагинацией
- Страница `/customers/[id]` с историей заказов
- Редактирование данных клиента

### Этап 4 — Товары (Приоритет: Высокий)
- Страница `/products` с фильтрами
- Форма создания и редактирования товара
- Загрузка изображения (POST `/api/upload`)
- Архивация и удаление

### Этап 5 — Dashboard (Приоритет: Средний)
- Подключение реальных данных из БД
- Графики на Recharts
- Топ-5 товаров

### Этап 6 — Полировка (Приоритет: Низкий)
- Toast-уведомления (Sonner)
- Адаптивность под планшет
- Подтверждения перед удалением
- Страница настроек

## 10. КРИТЕРИИ ПРИЁМКИ

Система считается готовой, если:

- [ ] Авторизация работает, неавторизованный пользователь не может попасть на защищённые страницы
- [ ] Менеджер не может выполнять действия, доступные только администратору
- [ ] CRUD-операции для заказов, клиентов и товаров работают корректно
- [ ] Фильтры, поиск и пагинация работают во всех списках
- [ ] История статусов заказа сохраняется при каждом изменении
- [ ] Загрузка изображения для товара работает
- [ ] Экспорт заказов в CSV работает
- [ ] Dashboard отображает реальные данные из БД
- [ ] Soft delete работает: удалённые записи не отображаются в интерфейсе
- [ ] Удаление товара с существующими заказами невозможно
- [ ] Все формы валидируются на стороне сервера (Zod)
- [ ] Пароли хранятся в зашифрованном виде
