# Документооборот: от заказа до оплаты

Дата: 2026-10-16
Статус: структура таблиц создана (`prisma/schema.prisma`), нумерация посылок и задач настроена. Экранов для новых документов пока нет.

---

## 1. Цепочка документов

Каждый документ — отдельная таблица в одной базе. Рядом указаны таблица и префикс номера.

```
Заказ                                   Order              ZK
├─ Сортировка                           Sorting            SR
├─ Приём заказа                         Receiving          PR
│   └─ Раскладка                        Placement          RS
├─ Задача на формирование посылки       ParcelTask         как в Excel: AT1536DE
│   ├─ В работе                         статус задачи IN_PROGRESS
│   ├─ Сборка                           Assembly           SB
│   ├─ Упаковка                         Packing            UP
│   ├─ Взвешивание                      Weighing           VZ
│   └─ Посылка                          Parcel             PS
│       ├─ Комплектация коробов         Box                KR
│       ├─ Реестр отправки              Manifest           RO
│       │   └─ Документы AWB            Awb                AW
│       │       ├─ Счёт на оплату услуг         AgentInvoice  SA
│       │       │   └─ Заявка на выплату агенту AgentPayout   VA
│       │       └─ Счёт на оплату услуг         AgentInvoice  SA
│       │           └─ Заявка на выплату агенту AgentPayout   VA
│       ├─ Заявка на пополнение баланса клиента TopUpRequest  PB
│       │   └─ Приход ДС                        Payment       PD
│       │       └─ Распределение оплат по посылкам PaymentAllocation RP
│       └─ Изменение долга клиента              ClientLedger  DK
```

## 2. Правила связей

- **Одна коробка от продавца = один заказ.** Под одним треком продавца может быть несколько заказов (несколько коробок).
- **Много заказов → одна посылка.** Один заказ не делится на несколько посылок.
- **Заказ попадает в посылку через задачу.** Заказы выбираются в задачу на формирование посылки, задача создаёт посылку.
- **Нынешний «Заказ» из Excel — это посылка.** Модель `Order` переименована в `Parcel`, раздел админки `/orders` — в `/parcels` («Посылки»). Поле «Посылка» (трек-номер) теперь подписано «Трек-номер посылки».
- **Посылки, импортированные из Excel, не имеют заказов.** Номер строки Excel (`AT1536DE`) стал номером их задачи, задача создана со статусом «завершена». Новые посылки проходят весь путь.

| Связь | Как устроена |
|---|---|
| Заказ → Сортировка, Приём | Один к одному (`orderId @unique`). Сортировка может быть без заказа, если клиент не опознан |
| Приём → Раскладка | Один к одному, раскладка ссылается на ячейку `StorageCell` |
| Задача → Заказы | Один ко многим (`Order.parcelTaskId`) |
| Задача → Сборка, Упаковка, Взвешивание, Посылка | Один к одному (`parcelTaskId @unique`) |
| Сборка → Заказы | Строки `AssemblyItem`: заказ и отметка «найден» |
| Посылка → Короб → Реестр → AWB | Посылка в одном коробе, короб в одном реестре, у реестра может быть несколько AWB |
| AWB → Счета агентов → Заявки на выплату | Счетов сколько угодно (у каждого свой агент из справочника `Agent`). У счёта может быть несколько заявок на выплату (частичная оплата) |
| Заявка на пополнение → Приход ДС | Приход может ссылаться на заявку, а может прийти без неё |
| Приход ДС → Распределение → Посылки | Строки `PaymentAllocationItem`: посылка и сумма. Один приход может закрыть несколько посылок |
| Изменение долга | Строка журнала: сумма со знаком (+ долг вырос, − уменьшился), основание — посылка или распределение оплаты. Долг клиента = сумма строк |

## 3. Данные документов (стартовый набор, будет дорабатываться)

У всех документов есть: номер, дата создания, сотрудник (`createdBy`), комментарий (`note`), мягкое удаление (`deletedAt`).

| Документ | Свои данные |
|---|---|
| Заказ | Клиент, входящий трек-номер (китайская служба: SF, J&T…; поле `incomingTrackNumber`, не путать с номером документа ZK-…), описание содержимого, статус, задача |
| Сортировка | Входящий трек-номер, определённый клиент, клиент опознан или нет |
| Приём заказа | Количество мест, вес при приёме, состояние (целый / повреждён), фото |
| Раскладка | Ячейка хранения |
| Задача на формирование посылки | Клиент, страна доставки, статус. Приписки из Excel («01 DHL», «Sea») — в примечании |
| Сборка | Какие заказы собраны, все ли найдены |
| Упаковка | Тип упаковки, количество мест |
| Взвешивание | Вес, габариты (Д × Ш × В), объёмный вес |
| Посылка | Все прежние поля заказа из Excel + задача и короб. Трек-номер посылки (международный: LC…MG, EV…CN, 00340…) — поле `parcelNumber`, не путать с номером документа PS-… |
| Короб | Реестр, вес |
| Реестр отправки | Дата отправки, страна назначения |
| Документы AWB | Номер авианакладной перевозчика, перевозчик, рейс, дата вылета |
| Счёт на оплату услуг | Агент, AWB, номер счёта агента, дата, сумма, валюта |
| Заявка на выплату агенту | Счёт, сумма, валюта, статус, дата оплаты |
| Заявка на пополнение баланса | Клиент, сумма, валюта, статус |
| Приход ДС | Клиент, заявка, сумма, валюта, способ оплаты, дата поступления |
| Распределение оплат | Приход, строки «посылка — сумма» |
| Изменение долга клиента | Клиент, сумма, валюта, причина, посылка или распределение |

Валюты: `CNY` (по умолчанию) и `USD`.

## 4. Статусы

**Заказ** (`OrderStatus`): NEW — создан, SORTED — отсортирован, RECEIVED — принят, PLACED — разложен, IN_TASK — в задаче, IN_PARCEL — в посылке, CANCELED — отменён.

**Задача на формирование посылки** (`ParcelTaskStatus`): NEW — создана, IN_PROGRESS — в работе, ASSEMBLED — собрана, PACKED — упакована, WEIGHED — взвешена, COMPLETED — посылка создана, CANCELED — отменена.

**Посылка** (`ParcelStatus`) — прежние статусы заказа без изменений.

Задумано, что статус меняется сам при создании документа этапа (провели раскладку — заказ «Разложен»). Эта логика появится вместе с экранами документов.

## 5. Номера документов

Номер документа — его порядковый номер в таблице с префиксом: `PS-000001`. Префикс — латиница по первым буквам русского названия: латиницу без проблем читают сканеры штрихкодов и китайский склад. Префиксы и выдача номеров — в `lib/document-numbers.ts`, счётчики — в таблице `DocumentCounter`.

**Исключение — задача на формирование посылки.** Её номер как в Excel: код клиента + порядковый номер + страна доставки, например `AT1536DE`. Так сотрудникам и клиентам не нужно привыкать к новым номерам.
- Порядковый номер общий для всех клиентов. Для старых записей он взят из Excel, новые задачи получают следующий после максимального из Excel.
- Номер собирается при создании задачи и больше не меняется. Для этого нужны код клиента и страна.
- Приписки после номера (`01 DHL`, `Sea`) в номер не входят — пока они в примечании задачи.
- Если в Excel один номер встречался несколько раз (`AT1536DE 01 DHL` и `AT1536DE 02 DHL`), вторая задача получает `AT1536DE-2`, исходный номер — в примечании.

## 6. Обновление существующей базы

Для базы, созданной до этих изменений, — один раз, именно в таком порядке:

```bash
npm run db:upgrade:001   # переименовывает таблицы Order → Parcel, данные сохраняются
npm run db:push          # создаёт новые таблицы документов
npm run db:upgrade:002   # посылки получают номера PS-…, номера Excel переходят в задачи
```

Если базу уже обновляли первыми двумя командами, достаточно `npm run db:push` и `npm run db:upgrade:002`.

- Если запустить `db:push` без первого шага, Prisma остановится с ошибкой и ничего не удалит.
- Повторный запуск `db:upgrade:001` и `db:upgrade:002` безопасен: скрипты ничего не меняют.
- Номер, который не разобрался как номер задачи (например, `ORD-2024003` из админки), сохраняется в примечании посылки: «Прежний номер: …».
- Для новой пустой базы достаточно `npm run db:push` и `npm run db:seed`.

## 7. Открытые вопросы

1. Все заказы в одной посылке всегда принадлежат одному клиенту? Сейчас задача и посылка привязаны к одному клиенту.
2. Сортировка: что именно сортируют, и бывает ли сортировка до появления заказа (неопознанная коробка)? Сейчас это допускается.
3. Два «Счёта на оплату услуг» под AWB — от каких агентов? Сейчас счетов может быть сколько угодно.
4. Один реестр отправки всегда соответствует одной AWB? Сейчас у реестра может быть несколько AWB.
5. Когда меняется долг клиента: автоматически при взвешивании / создании посылки и при распределении оплаты, или вручную?
6. Приписки к номеру задачи (`01 DHL`, `Sea`): что означает `01`, и нужно ли отдельное поле «способ доставки»? Если `01` и `02` — части одной отправки, у одной задачи может быть несколько посылок.
7. В старых записях поле «Трек-номер посылки» заполнено из колонки Excel «Номер посылки», и там встречаются треки китайских служб (SF, J&T). По новой логике это входящий трек-номер заказа. Переносить ли их куда-то?
